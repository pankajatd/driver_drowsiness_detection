## 1. Defect Description
On cloud container runtime environments running Python 3.14 (Debian Trixie / Streamlit Community Cloud), Google MediaPipe binary wheels are not compiled by upstream Google. When initializing `DriverDrowsinessDetector`, the application threw `RuntimeError: Google MediaPipe FaceMesh is not supported on Python 3.14`, causing Streamlit Cloud to halt with `st.error()` and `st.stop()`.

## 2. Steps to Reproduce
1. Deploy the application on Streamlit Community Cloud with Python 3.14 runtime.
2. Launch the application URL: `https://driverdrowsinessdetection-2yyqw9wm6bftedvf75cpgv.streamlit.app`.
3. Observe perception engine initialization failure banner and halted execution.

## 3. Expected vs. Actual Behavior
- **Expected:** The perception engine should gracefully adapt to host Python environments and provide resilient facial telemetry without halting the UI.
- **Actual:** Execution stopped immediately with initialization error banner.

## 4. Root Cause Analysis
`mediapipe` only distributes C++ binary `.so` wheels for Python 3.8 through 3.12. On Python 3.14, `import mediapipe.solutions.face_mesh` fails with `AttributeError`. The detector lacked a non-MediaPipe fallback pipeline.

## 5. Developer Resolution (Applied by Software Developer Agent)
- Implemented a zero-dependency **OpenCV Computer Vision Fallback Engine** in `src/detector.py`.
- Automated detection via YCrCb skin segmentation, morphological oval filtering, and landmark synthesis.
- Removed halting `st.error()` and `st.stop()` in `src/app.py` and replaced with active engine status badge:
  `⚡ Perception Engine: Active (OpenCV Vision Mode - Cloud Container)`.
